# 동시성·충돌

여러 사람이 같은 업무를 동시에 고칠 때와 복제본이 여럿일 때의 장치를 정리합니다.


| 장치 | 키·값 | 내용 |
|---|---|---|
| 문서 잠금 | `tasks:doc:{컬렉션}:{id}` · TTL 15초 · 대기 3초 | 업무·규칙·휴지통 한 건의 「읽기→고치기→쓰기」. 못 잡으면 409 「같은 업무를 다른 사람이 저장하는 중입니다」 |
| 생성 잠금 | `tasks:gen` · TTL 60초 | 레플리카 사이에 생성은 한 번에 하나 |
| 공휴일 잠금 | `tasks:holidays` · TTL 15초 · 대기 5초 | 못 잡으면 409 |
| 잠금 표 | 저장소 `locks` 표(복제본 공통). 획득은 한 문장(`INSERT … ON CONFLICT … WHERE 만료 OR 같은 소유자`) | architecture.md |
| holder | 잠글 때마다 무작위 `holder`, 풀 때 `store.release_lock(key, holder)` — **내가 잡은 것만** 지움(TTL 이 지나 남이 잡은 잠금을 지우지 않게) | `store_lock` |
| 예약 접두 | `tasks:` 로 시작하는 키는 범용 `/api/lock/*` 로 잡거나 풀 수 없음(403) | `LOCK_RESERVED_PREFIX` |
| 잠금 순서 | **`tasks:gen` → `tasks` 문서 → `taskTrash` 문서** 고정. 생성은 문서 잠금을 잡지 않고, 문서 잠금을 잡은 채 gen 을 기다리는 곳이 없어 교착 없음 | 지우기 tasks→trash, 복원 (gen→)tasks→trash, 영구 삭제 trash 만 |

## 칸 단위 충돌 확인(`_base`, `task_conflicts`)

1. 화면은 펼침·창을 연 때의 값과 비교해 **바꾼 칸만** 보내고 `_base:{칸: 연 때 값}` 을 붙입니다.
2. 서버는 문서 잠금 안에서 지금 값을 읽고, **보낸 칸 중 `_base` 에도 있는 칸**마다 비교합니다.
3. 정규화 비교(`_base_norm`): 없음·`null`·`""`·`false` 는 같음. 문자열은 줄바꿈 제거·공백 연속 한 칸·앞뒤 공백 제거.
4. 지금 값 ≠ `_base` 값이고 지금 값 ≠ 보낸 값이면 충돌 → 저장하지 않고 409 `{detail, conflicts:[칸], task:{지금 행}}`.
5. `_base` 의 칸 이름은 `TASK_FIELDS` 12개만 인정. `_base` 가 없거나 빈 객체면 비교 없이 저장(마지막 저장이 이김 — 엑셀·목록 완료 체크칸·옛 호환). 객체가 아니면 400.
6. 409 에 지금 값을 실으므로, 그 전에 못 보는 업무 404·고칠 수 없는 사람 403 을 먼저 거릅니다.
7. 충돌 확인 **뒤에** 완료 일시 찍기·담당자 변경 상태 규칙이 돕니다.

## 담당자 변경 때 상태(`_tasks_edit`)

| 경우 | 결과 | 이력 action |
|---|---|---|
| 원래 '예정' 아님 + 새 시작일 미도래 | '예정'으로, 완료 정보·`autoStarted` 비움 | 「담당자 변경 (상태 진행 → 예정)」 |
| 시작일 이미 도래(`_auto_due`) | 그 저장에서 바로 '진행' + `autoStarted:true` | 「담당자 변경 (상태 완료 → 진행, 시작일 도래)」 / 원래 진행이면 「… (상태 진행 유지 — 시작일 지남)」 |
| 원래 '예정' + 시작일 없음·미래 | 상태 그대로 | 「수정」 |

## 복제본 전제

- 운영은 컨테이너 앱 복제본이 여럿일 수 있다는 전제로 짰습니다(잠금·SSE 모두 저장소 경유). 실제 운영 복제본 수는 **확인 필요**(코드에 없음 — Azure 설정).
- PostgreSQL 은 `LISTEN/NOTIFY` 로 모든 복제본에 변경을 알리고, SQLite(로컬)는 프로세스 안에서 알립니다.

## 삭제·복원 순서

| 동작 | 순서 |
|---|---|
| 지우기 `DELETE /api/tasks/{id}` | tasks 잠금 → trash 잠금 → (생성 건이면) `taskSkips` 기록 → `taskTrash` 저장 → `tasks` 삭제 |
| 되살리기 | (생성 건이면 `tasks:gen` 5초) → tasks 잠금 → trash 잠금 → 같은 id 있으면 409 → `tasks` 저장(이력 「복원」) → `taskSkips` 에서 빼기(`drop_skip`, 생성 건만) → `taskTrash` 삭제 |
| 영구 삭제 | trash 잠금 → `taskTrash` 삭제(`taskSkips` 유지 → 다시 안 생김) |

- 생성 건 복원에 생성 잠금이 필요한 까닭: 생성이 「업무 목록 → taskSkips」 두 번 읽는 사이에 복원이 끝나면 생성이 「업무 없음 + skip 없음」으로 보고 되살린 업무를 덮어씁니다(저장 순서만으로는 못 막음).
- `drop_skip` 은 merge 에 값 `None` 을 주어 그 키만 지웁니다(PG `SELECT … FOR UPDATE`, SQLite 쓰기 잠금). 키가 없으면 부르지 않습니다(없는 문서에 merge 하면 `null` 칸이 남음).
