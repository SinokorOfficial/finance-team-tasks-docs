# 자료 원천·결과물

업무 자료가 어디서 들어오고, 무엇이 만들어져 나가는지 정리합니다.


| 원천 | 들어오는 길 | 비고 |
|---|---|---|
| 사람 입력 | 화면 [＋ 업무 등록] → `POST /api/tasks`, 수정 `PATCH /api/tasks/{id}` | 등록자·등록 시각은 서버가 찍음 |
| 엑셀 일괄 등록 | 양식 `GET /api/tasks/template.xlsx` → 미리보기 `POST /api/tasks/import-preview`(xlsx 원문) → 등록 `POST /api/tasks/bulk` | 5MB·500행까지, 하나라도 규칙 위반이면 전부 미등록 |
| 반복 규칙 자동 생성 | `taskTemplates` 규칙 → `generate()` | 목록 조회 때 이번 달·다음 달, [규칙에서 생성]으로 1~12달 |
| 포털 「일정」에서 업무 만들기 | 일정 상세 창 [업무로 만들기] → `tkHub.newFrom()` 이 새 업무 창을 채움 | 화면 안 동작. 저장은 사용자가 [등록] (= `POST /api/tasks`) |
| 공휴일 | `server/holidays.py` 내장 목록(2026년 22일·2027년 24일) + 관리자 추가·제외(`meta/holidays`) | **외부 공휴일 API 연동 없음** |

- **외부 API 연동: 없습니다.** 업무 현황 절(`app.py` 2176~3460행)과 `holidays.py` 에 외부 HTTP 호출이 없습니다. 메일 발송도 하지 않습니다(설정만 보관).
- 포털 「일정」 기능의 사내 API 동기화(evsync)는 별개 기능이며, 업무 현황은 그 결과를 읽지 않습니다. 「일정에서 업무 만들기」는 화면에서 일정 칸 값을 복사하는 것뿐입니다.

## 결과물


| 결과물 | 형태 | 위치·주소 |
|---|---|---|
| 업무 현황 화면 | 탭 4개: 현황 · 캘린더 · 휴지통(담당자·관리자) · 관리(관리자) | 포털 메뉴 「업무 현황」, 주소 `/#tasks`, `GET /go/tasks` → `302 /#tasks` |
| 포털 「일정」 달력 겹쳐 보기 | 「업무 기한 표시」 켜면 미완료 업무 기한 표시(◆) | `tkHub.dueList()` 사용, 일정 보기 |
| 엑셀 내보내기 | xlsx 19열(기한·업무명·담당자·상태·시작일·구분·회사·관련 기관, 부서·관련 선박·프로젝트·외부 기한·개인 업무·메모·등록일·등록자·완료일·완료자·반복 규칙·최근 수정·id), 파일명 `업무현황_YYYYMMDD.xlsx` | `GET /api/tasks/export.xlsx` |
| 엑셀 일괄 등록 양식 | 시트 「업무등록」(머리글 12열·예시 2행·드롭다운) + 시트 「안내」(규칙·담당자 목록), 파일명 `업무등록양식_YYYYMMDD.xlsx` | `GET /api/tasks/template.xlsx` |
| 저장 자료 | 포털 PostgreSQL `docs` 표(jsonb)의 컬렉션 — [데이터 모델](data-model.md) 참고. **새 표·DDL 없음** | 운영: PostgreSQL 스키마 `fnc` / 로컬: SQLite |

- 엑셀 시각 칸(등록일·완료일·최근 수정)은 저장된 UTC 를 한국 시각으로 바꿔 적습니다(`astimezone(KST)`).
- 화면 「3. 기간별」에서 「위에 이미 나온 n건」으로 접힌 업무도 내보내기 파일에는 들어갑니다(화면 건수 ≠ 파일 건수, 의도).
